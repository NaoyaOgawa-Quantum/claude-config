# WebGL の f32 数値計算と f64 参照の組み方

物理量を shader で計算する viewer では、 **f64 の参照実装 (Python 等) を正本**にし、 shader はその式の f32 版とする。 以下はその組み方で、 どれも実測に基づく。 式そのものの正本は各 project の参照実装の docstring に置き、 shader の注釈はそこを指す。

## <a id="table-domain-extension"></a>事前計算 table の端は物理の境界ではない

lookup table (texture) で写像を持つとき、 table の最大引数は texture の都合で決まった端にすぎない。 利用者が端の外へ出られるようにするには、 **table を大きくして上限を先送りするのではなく、 外側を厳密に継ぐ**:

1. 写像を「強い領域 (table が担う)」 と「弱い領域 (解析的に扱える)」 に**厳密に分解**する。 例: 光線の曲がり角 = (table の端の半径までの寄与、 table の最終行から読む) + (端から観測者までの脚の積分)。 脚は被積分関数が穏やかなので shader 内の低次の求積 (Gauss–Legendre 12 点程度) で足りる。 同じ脚は、 同じ table を別の半径で読む他の層 (例: 軌道 table を使う物体の描画) の延長にもそのまま使える。
2. **近似の差分引き継ぎを使わない**: 「table 端での値と平坦極限の差を定数として持ち越す」 形は、 脚の寄与の一部を落とす (被積分関数の違いの積分がそのまま誤差になる)。 実測で目に見える大きさになった。 採るかどうかは、 f64 の厳密解と比べた数値で決める (推測で固定しない)。
3. **継ぎ目を分岐点に置かない**: 分解の境目 (どの入力を table 側に回すか) を、 写像が平方根の分岐点を持つ所 (例: table の端をかすめる光線) に置くと、 table 側と積分側に逆向きの √ε_f32 (≈ 3e-4) 程度の丸めが残る。 境目は分岐点から離れた所に取る。
4. 端でちょうど table と一致すること、 端の前後で連続なこと、 遠方で平坦極限に近づくこと、 厳密解との一致、 分岐の継ぎ目で連続・単調なことを参照実装の selftest に持つ。

## <a id="f32-conditioning"></a>f32 の条件付け

| 危険 | 起きること | 回避 |
|---|---|---|
| 90° 付近の `sin` | `|θ − 90°| < 3.5e-4 rad` で f32 の `sin θ = 1` になり、 sin から作った量 (衝突径数など) がずれの情報を失う | 小さなずれは `cos θ` (またはベクトルの成分) から作る。 解析的な恒等式で差を直接表す (例: 転回点までの距離 `w_p − w_R` を `cot²θ` の式で作る) |
| `acos(c)` の `c ≈ ±1` | √ε の誤差 (角度が小さいほど相対的に大きい) | `atan(|a × b|, a · b)`、 または横成分の長さを sin として使う |
| 小角での `sqrt(1 − c²)` | 遠くの小さな物体 (視角 ≪ 1) で c ≈ 1 の差が桁落ちする | 横成分の長さ (上と同じ) を使う |
| 積分端点の平方根特異性 (転回点) | 固定の求積点が特異性に吸われる | 根 `w_p` で因数分解し `w = w_p − t²` に置換 (被積分関数が滑らかになる)。 区間幅は `(w2 − w1)/(t1 + t2)` で作り、 `t1 − t2` (桁落ち) を作らない |
| 冪の溢れ | `p³` などが大きな引数で f32 を溢れる | 逆数変数 (`w = 1/p`) で解く。 固定点反復なら単調性と縮小率で収束を保証し、 反復回数を固定する |
| 定数の精度 | shader 側で求積点を計算すると f32 で丸まる | Gauss–Legendre の点・重みは f64 で出して literal で埋める |

## <a id="f32-emulation-gate"></a>f32 emulation を export の関門にする

参照実装の関数に dtype 引数を持たせ、 **同じ算術を `np.float32` でも回す** (NumPy 2 の NEP 50 で Python の float は弱い型 = float32 のまま進む。 定数は明示的に `dt(…)` で包む)。 shader と同じ table の読み方 (最終行・線形補間) も f32 で写す。 これで厳密解との差を測り、 texture を書き出す script の出力と metadata に「f32 誤差」 として残す (= 公開前の関門)。 厳密解側の許容誤差 (例: `scipy.integrate.quad` の既定 1.5e-8) を閾値の下限として扱い、 それより細かい一致を要求しない。

## <a id="probe-channel"></a>色でなく計算値を画素に書く probe channel

shader の実出力を f64 と照合するには、 検証用の uniform で**色の代わりに計算値を書き出す**:

- 値を 24 bit の固定小数に直して RGB に分けて書く (`floor(v · 2²⁴)` を 65536 / 256 / 1 に分解、 `v ∈ [0,1)` になるよう offset と scale)。 欠損 (影など) は 0 を sentinel にする。 精度は scale / 2²⁴。
- 読み戻しは `preserveDrawingBuffer: true` + `readPixels(RGBA, UNSIGNED_BYTE)`。 dithering を切る (`gl.disable(gl.DITHER)`)。
- 画素の方向は返さず、 **camera 基底・画角・canvas 寸法を返して、 f64 側で画素中心の方向を shader と同じ式で組み直す** (戻り値を小さく保つ)。 f64 側で観測者の boost 等も独立に再計算し、 参照実装の写像と比べる。
- 検証用の描画は**時間を進めない** (1 回描く hook は dynamics の積分を呼ばない) = 照合中に状態がずれない。 描画 loop が止まっていても (pane が隠れている等) 同期的に描いて読める。
- 大きな戻り値を file に落とすときは書き写さない → [`preview.md#browser-pane-visibility`](preview.md#browser-pane-visibility) の transcript からの取り出し。

## <a id="seam-pixel-diff"></a>継ぎ目の連続性を実画面で測る

分岐の継ぎ目 (table 端など) の前後で、 観測者を微小に動かした 2 枚の画素差を取るだけでは判定できない (grid 線などの縁の画素が入れ替わる基準の差がある)。 **継ぎ目をまたぐ差を、 またがない同じ幅の差と比べる**。 特定の物体だけを見たいときは「その物体を描いた画像 − 描かない画像」 が 0 でない画素で mask してから比べる。

## <a id="frame-time-budget"></a>実時間 simulation の 1 frame の時間予算

描画が止まった後に一気に進んで「ワープ」 しないよう、 経過時間は捨てずに借り (time debt) として繰り越し、 1 frame に返す量に上限を置く。 このとき上限を**定数にすると、 時間の倍率を上げても simulation が上限で頭打ちになり**、 借りも際限なく溜まる。 上限は「倍率 × min(その frame の実時間, 上限時間) × 1.5 程度」 にする (通常の frame rate では追いつき、 停止直後の 1 frame だけ上限時間で抑えられる)。

## <a id="generated-asset-noise"></a>再生成した binary 資産の公開

f64 の table を再生成すると、 数値計算の非決定性で f32 の最下位桁だけ揺れることがある。 **公開用の copy の前に、 公開済みの版と数値で比べる**: 差が最下位桁だけなら公開済みの版を据え置き、 公開 repo に中身の同じ MB 単位の差分を積まない。 比べずに copy → commit しない。
